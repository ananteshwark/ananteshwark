Test report · Round 2

Where the AI Falls Short

The contract system now matches the incumbent CLM suites on features. Benchmarked against the tools whose whole pitch is AI, two things separate us: the AI never acts, and nothing guarantees it is right.

The measurement that matters

Semantic search and the “ask your contracts” feature both present as working — endpoints return results, tests pass, the interface is finished. So I scored known paraphrase pairs directly through the production embedding function.

Two genuine paraphrases score below the unrelated baseline. The embedding matches characters, not meaning — so “semantic” search and the retrieval feeding Q&A are fuzzy keyword matching. Tests pass because their fixtures share vocabulary.

Verdict

Three findings, in the order they should be acted on.

The AI has no quality floor

Retrieval is lexical, citations are never validated, there is no eval set and no record of whether a human accepted any AI output. Nothing would reveal a regression tomorrow.

The AI is advisory, never agentic

We detect, flag and summarise. The leaders propose the actual redline, draft the counter-offer and pre-fill the intake. A reviewer still does every keystroke here.

Shipped work sits disconnected

Playbooks, obligations, risk and spend all work individually but were never wired to each other — or onto the dashboard. Cheap to fix, immediately visible.

How this was tested

Not a paper review. I booted the app on a clean database, seeded a super-admin and probed the REST surface with a real token — 33 routers, roughly 200 endpoints. I walked the full path a contract takes (register → draft → review → approval → signature → obligation) looking for breaks between the features shipped across Phases A–E, audited statically whether each feature actually feeds the next, and measured retrieval quality directly rather than trusting that the endpoint returned rows.

Findings

Twenty gaps, grouped by the kind of work each needs. The stripe encodes class, not priority — sequencing comes later.

Class 2

AI quality & trust — highest risk

09

“Semantic” search is lexical

The hashing embedding scores character n-grams, not meaning. A true paraphrase can score below unrelated text, so both search and RAG retrieval are fuzzy keyword matching.

measured: 0.165 paraphrase < 0.174 noise
10

Citations are never verified

The prompt asks the model to cite [#n]. Nothing checks that the cited contract was retrieved, or that the claim appears in it. A confident wrong answer looks exactly like a right one.

no validation in repository_ai_api.ask
11

No record of AI output

Nothing stores what the model produced, which prompt and model version made it, or whether the human accepted it — required by most legal-ops AI policies, and the signal needed to improve.

12

No eval harness

No golden set, no regression gate. Any prompt or model change ships blind.

13

One model for every task

Extraction, summarisation, obligations, gap analysis and Q&A share a single configured model — no per-feature routing, no cheap/expensive tiering, no fallback chain.

14

Retrieval is O(n) in Python

Every contract's vector is loaded and scored per query. Fine at hundreds, unusable at 50k. No ANN index, no pgvector.

Class 3

Agentic capability — the frontier gap

15

No auto-redline

We map third-party clauses and score deviation, then stop. The leaders emit the concrete replacement text as tracked changes, ready to accept.

16

No negotiation copilot

No counter-language with rationale, no recall of what this counterparty conceded last time — despite a negotiation ledger already existing.

17

No per-contract Q&A

Ask is repository-wide only. You cannot interrogate the contract you are currently reading — table stakes elsewhere.

18

No multi-contract comparison

“Compare the liability caps across these five NDAs” has no answer short of opening each one.

19

No intake copilot

Requests are typed into a form by hand. No natural-language intake that classifies the type, picks the template and pre-fills the draft.

20

No email or mobile approval

Approvers must log into the app. The tokenized-action pattern already built for renewals would cover this.

Class 1

Integration debt — built, never connected

01

Six pages are ungoverned

Reviews, Requests, Tasks, Repository AI, Obligations and Report Builder are missing from the page-access catalogue, so admins cannot restrict them. Unknown keys default to visible.

catalogue lists 17 pages; nav renders 23
02

Obligations never trigger reminders

They appear in the digest only. The reminder engine — with offsets, escalation and recipients — knows contract expiry but not obligation due dates, so the extract→track→chase loop never closes.

03

The dashboard predates four phases of work

No obligations, no risk, no cycle-time, no spend. Everything built since Phase A is invisible on the landing page.

04

Obligation extraction is manual

The AI abstract and embedding run automatically at validation; obligations require someone to click, per contract.

05

Only drafts can be risk-scored

Executed contracts in the register cannot be scored against the playbook at all, so there is no portfolio risk position.

GET /contracts/{id}/deviations → 404
06

Risk scores are computed then discarded

Never persisted — so no trend, no report column, no filter, no approval gate, no alerting.

07

Global search misses half the system

Returns contracts, vendors and text matches — not drafts, clauses or obligations.

08

No bulk obligation actions

The portfolio view lists hundreds; each must be ticked individually.

Roadmap

Five phases, lettered to continue from the shipped A–E. The order encodes dependency: G unblocks H and J, and I ships alongside H rather than after it.

G

Make retrieval real

The foundation every other AI feature stands on. Treat as correctness, not enhancement.

G1

Real embeddings, offline. Bundle a small CPU sentence-transformer (~80 MB) in the tarball; keep hashing as the no-model fallback; re-index in place.

M
G2

Vector index at scale. pgvector + HNSW on Postgres, in-memory path retained for SQLite.

M
G3

Hybrid retrieval. Trigram/BM25 fused with vector by reciprocal rank — each covers the other's failure mode.

M
G4

Citation enforcement. Validate every [#n] against what was retrieved and the supporting span; strip or flag unsupported claims.

M
G5

Per-contract Q&A and comparison across N contracts as a structured table.

M
H

Agentic drafting & negotiation

The differentiator. Builds on playbook tiers and the tracked-changes engine already shipped.

H1

Auto-redline third-party paper. Generate the replacement from the standard or fallback tier and emit it as individually accept/rejectable tracked changes.

L
H2

Negotiation copilot. Counter-proposal with rationale, informed by this counterparty's concession history; drafts the reply.

L
H3

Intake copilot. Natural language → classify type → select template → pre-fill → route.

M
H4

Email and mobile approval via signed one-tap links, reusing the renewal token pattern.

M
I

AI governance & trust

Ships with H, not after. Legal teams will not run agentic AI without it.

I1

AI output audit. Persist feature, prompt version, model, input hash, output, latency and the human accept / reject / edit.

M
I2

Eval harness. A golden set per feature with scored regression runs in CI.

M
I3

Prompt & model registry. Versioned prompts per feature, per-feature routing, fallback chain, cost and latency budget.

M
I4

Confidence & abstention. Surface retrieval confidence; abstain rather than guess on weak evidence.

S
J

Portfolio intelligence

Needs F and G landed first — structured extraction is only as good as retrieval.

J1

Structured clause attributes. Extract “liability cap = 12 months fees” as queryable data, so “every contract with uncapped liability” is a filter, not a search.

L
J2

Risk trending & alerts. Portfolio risk over time, concentration and exposure analytics, threshold alerts.

M
J3

Bulk AI operations. Batch summarise, extract and score with progress and resumability.

M

Recommended sequencing

First, ~2 wks

F1 · F4 · F7 · I4 — small, self-contained, and they make four phases of existing investment visible.

The unlock

G1 → G2 → G3 → G4 — until retrieval is real, every AI feature built on top inherits a weak foundation. G1 alone is the highest-leverage change in this document.

Differentiator

F5 → H1 → H2, shipped with I1 + I2 so agentic output is auditable and regression-tested from day one.

Then

F2 · F3 · F6 · H3 · H4, then Phase J.

Still out

Cloud model APIs as a hard dependency, public-IdP SCIM, SaaS procurement connectors, vendor-hosted analytics — all remain out of scope for an air-gapped install.

One risk to flag explicitly

Finding 09 is the most under-appreciated item here. Semantic search and Q&A both look finished — endpoints return results, tests pass, the UI is complete — but retrieval cannot match a paraphrase. Users will trust the answers precisely because the interface presents them confidently.

Combined with finding 10, unverified citations, that is the highest-risk behaviour in the system today. G1 and G4 should be scheduled as correctness fixes, not enhancements.
